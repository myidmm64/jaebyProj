# TestStage 전투 실행

Assets/Scenes/TestStage.unity를 열고 Play한다. 별도 ManaPrototype 씬·UI·씬 생성기·검증기는 제거했다. GameManager가 Stage.Init() 후 StageCombatController를 연결한다. Stage의 유효 셀, GetCellCenterWorld, 기존 Player/Enemy(GridObject)와 타일맵을 사용한다. 전투 규칙은 BattleState.cs에 보관한다.

## 조작

- 하단 6칸 시퀀스는 항상 표시된다. 가방은 Tab 또는 가방 버튼으로 연다.
- 가방 카드 → 슬롯: 장착. 슬롯 → 다른 슬롯: 교환. 슬롯 → 가방 영역: 보관. 같은 ID·성급 카드 위에 놓으면 합체하고 수명이 회복된다. 잘못된 곳에 드롭하면 원상 유지한다.
- 이동은 공통 계열 이동 카드로 실행한다. 시작 덱에 무제한 이동 카드 1장을 지급하며 ★1/★2/★3의 이동 범위는 2/3/4칸이다. 3웨이브마다 보상 후보에도 이동 카드를 넣는다. 시퀀스 실행 중 이동 카드 차례에 노란 점을 선택하면 경로를 따라 이동한 뒤 다음 카드가 실행된다. 선택하지 않고 이동 건너뛰기도 가능하다. 이동 카드가 없으면 무료 이동은 없다.
- 세팅 단계에서 카드 순서를 정한 뒤 시퀀스 시작을 누른다. 방향 선택과 회전은 없으며 카드에 표시된 고정 상대 타일을 그대로 적용한다. 실행 중 카드 편집은 막는다. 이동 뒤 카드의 예상 피해는 목적지 미정이므로 이동 후 결정으로 표시한다.
- 공격 실행: 카드가 차례로 확대되고 범위가 주황색으로 강조된 뒤 실제 피해·충전이 적용된다. 카드와 카드 사이 짧은 대기 후 적 행동, 수명 정리, 다음 턴으로 넘어간다.
- 코스튬·궁극기·합체·웨이브 보상은 기존 카드 기획 규칙을 유지한다. 새 이미지 생성은 하지 않았다.

## 구조

- BattleState.cs: 카드 정의·범위·BFS 이동 선택·합체·마나·순차 실행·수명·적·보상.
- StageCombatController.cs: 실제 씬 캐릭터 동기화, 월드 위 셀 표시, 하단 시퀀스·가방·실행 애니메이션.
- UI/CardDragHandle.cs 및 CardDropTarget.cs: uGUI 드래그·드롭. 드롭이 완료된 뒤 화면을 갱신해 드래그 객체가 도중에 사라지지 않게 한다.
- 기존 BagPanelUI 프리팹은 편집용 원본을 보존하고 전투 시작 시 비활성화한다. 이전 스크립트가 새 UI와 동시에 Tab 입력을 처리하지 않는다.
- 기존 TestStage의 잘못된 enabledCells 직렬화 문자열 끝 문자 y를 제거했다. 144칸의 기존 배치는 유지했다.

## 검증

같은 Unity 버전의 분리 검증 프로젝트에서 실제 TestStage 씬과 기존 아트·프리팹을 불러와 Play 모드 검증했다. 셀 도달성·벽 차폐·이동 복귀·합체·수명·피해 예측·궁극기 만료 규칙과 슬롯 교환/장착/보관/합체 드롭 처리, 노란 셀 버튼, 실제 Player.Cell 이동, 시간차 순차 실행을 확인했다. 로그: Logs/TestStageIntegration.log. 화면 배치의 육안 검사는 수행하지 않았다. 임시 검증 프로젝트에서 Unity 검색 인덱스 초기화 예외가 출력되었으나 게임 검증은 통과했다.

## 드래그 개선

누른 위치의 오프셋을 유지하면서 카드를 즉시 들어 올린다. 고스트는 시각 요소만 복사하고 CanvasGroup을 직접 생성한다. 원본 드래그 스크립트는 고스트에 복제하지 않는다. 슬롯·가방 경계에서 48 UI 단위까지 드롭을 보조하며 후보를 노란색으로 강조한다. 가방을 닫아도 하단 가방 버튼에 드롭하면 보관할 수 있다. 노란 이동 점의 클릭 범위는 보이는 점보다 넓게 36 UI 단위로 둔다.

회귀 검증: Logs/DragMoveCheck.log에서 실제 포인터 들기·반복 드래그·CanvasGroup 생성·슬롯 및 가방 이동·이동 카드 대기와 후속 실행·이동 카드 없는 턴의 위치 유지를 확인했다.


## 컨셉 HUD 반영

왼쪽 현재 스탯·플레이어 도형 초상화·궁극기 세로 게이지와 버튼, 중앙 실제 전장, 아래 6장 카드 시퀀스, 오른쪽 아이템 빈 목록·원형 시퀀스 시작·현재 실행 진행도를 배치했다. 상단에는 웨이브·턴·골드·웨이브 보상 안내·설정 버튼이 있다. 아이템은 아직 게임 효과가 구현되지 않아 빈 상태로 표시한다. 골드는 웨이브 승리당 10을 받으며 사용처는 없다.

Tab으로 가방을 열면 시퀀스가 위로 이동하고 그 아래 보유 카드와 페이지 버튼이 함께 올라온다. 이동·드래그·공격 중에는 가방 입력을 제한한다. 초상화 아래 버튼은 코스튬 관리를 열고 설정은 사운드 켜기/끄기와 새 런 기능을 제공한다.

공격 범위는 플레이어 기준 좌표 그대로 적용한다. 카드 그림과 실제 판정은 같은 고정 우측 패턴을 사용한다. 이동 카드의 도달성은 전 방향 BFS를 계속 사용한다. 레이아웃은 StageCombatHUD.cs, 원형 도형은 UI/HudDisc.cs에 분리했다. 회귀 로그는 Logs/ConceptHUD-regression.log를 참고한다.


## 전체 화면 오버레이 수정

HUD는 기본 TestStage 카메라 위에만 겹쳐 표시한다. 런타임 카메라 viewport·위치·줌 조정 및 전장 테두리 코드를 제거했다. 원형 도형 HudDisc는 CanvasRenderer를 필수 컴포넌트로 지정하고 생성 시에도 명시적으로 추가한다. Logs/OverlayCheck.log에서 실제 Play 모드의 원래 카메라 유지, 모든 UI Graphic의 CanvasRenderer, 원형 버튼 포인터 raycast, 가방 열기·갱신의 오류 유무를 검증했다.


## 가장자리 HUD

웨이브·턴은 좌측 상단, 골드·보상·설정은 우측 상단, 스탯은 왼쪽 가장자리, 보유 아이템은 오른쪽 가장자리, 초상화·궁극기는 좌측 하단, 시작·진행도는 우측 하단으로 옮겼다. 시퀀스는 하단 중앙에 붙이고 Tab 가방은 그 위로 함께 이동한다. 웨이브·골드·스탯·아이템 패널은 완전 투명하며 장식 테두리와 빈 아이템 배경도 제거했다. 기본 카메라는 변경하지 않는다. 검증 로그: Logs/EdgeHUD-check.log.


## 배율·안정적 UI·축소 범위

TestStage의 기본 카메라 orthographic size를 7.5에서 6.25로 바꿔 맵과 캐릭터를 약 20% 크게 표시한다. 화면 영역은 전체로 유지한다. UI는 CombatUIElements.cs에서 기존 오브젝트를 재사용하며 HUD 전체 파괴·재생성을 제거했다. 갱신 시 버튼 리스너를 교체해 중복 입력도 방지한다.

기본 탄환과 관통탄은 고정 오른쪽 2칸, 폭렬창은 3칸, 폭렬은 바로 오른쪽 열 세로 3칸, 대폭렬은 오른쪽 3×3이다. 화염고리는 상하좌우 1칸을 유지한다. 이동 카드는 ★1/★2/★3에 1/2/3칸이다. 카드 그림·실제 판정·예측이 같은 패턴 정의를 사용한다. Logs/StableHUD-regression.log, Logs/StableHUD-objects.log에서 실행과 반복 갱신을 검증했다.



## 한글 표시와 기본 우측 방향

런타임 HUD는 Resources/UI/NanumGothic.ttf를 명시적으로 로드한다. 임의 폰트 탐색을 제거하고 Pixel Perfect 및 2배 글리프 렌더링 후 0.5배 표시를 적용했다. 텍스트의 논리적 배치 크기는 유지하며 세로 잘림을 방지한다. 모든 단방향 공격과 기본 CardUIData 범위는 오른쪽이며 이동·주변 공격은 전 방향이다. Logs/KoreanText-check.log에서 실제 표시 문자의 한글·기호 글리프, 폰트와 배율, HUD 재사용을 검증했고 Logs/RightFacing-regression.log에서 우측 공격·드래그·이동을 검증했다.


## 범위 중앙 표시·2칸 이동·턴별 시퀀스

카드 범위는 7×7 그림의 정중앙 파란 칸을 현재 위치로 표시한다. 모든 성급의 이동 카드는 최대 2칸이며 장애물·적을 통과하지 않는다. 시퀀스는 1턴 1칸에서 매 턴 1칸씩 개방해 6턴부터 최대 6칸이다. 첫 장착 카드는 이동 카드이고 나머지는 가방에 보관한다. 잠긴 슬롯은 개방 턴을 표시하고 드롭·클릭·실행·피해 예측 대상에서 제외한다. 웨이브를 마치는 턴도 턴 수에 포함하며 다음 웨이브에서 개방 수를 유지한다. 새 런은 1칸부터 시작한다. 검증 로그: Logs/SequenceGrowth-check.log.
